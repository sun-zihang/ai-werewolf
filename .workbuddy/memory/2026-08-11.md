## Cloudflare Pages 部署报错修复（用户贴构建日志：tsc not found → dist not found）

提交 2fba409 → 9045990 → 6d5ff7d，最终在 6d5ff7d 修好。根因是「双产物目录」与「v2 root strategy 找根 dist」。

### 两次报错根因
1. `sh: 1: tsc: not found`：Cloudflare Pages 默认只在仓库根 `npm ci`，不会递归装 `web/` 子目录依赖，根 `build` 脚本进入 web 后找不到 tsc。
2. `Error: Output directory "dist" not found`：Cloudflare 用 v2 root directory strategy，在仓库根跑 `npm run build` 后去**根目录**找 `dist`；而本仓库前端产物原本在 `web/dist`（同时被后端 Docker/CloudBase 托管 `web/dist`），根目录无 `dist`。

### 最终方案（单一真相源，已验证）
- `web/vite.config.ts`：`build.outDir` 改为 `'../dist'`（仓库根 dist）+ `emptyOutDir: true`。
- 根 `package.json` devDependencies 声明 `typescript`/`vite`（兜底根目录 tsc 可用），根 `build` = `npm --prefix web install && npm --prefix web run build`。
- `server/src/index.ts` 后端托管路径 `web/dist` → `dist`；`.github/workflows/pages.yml` 上传 `web/dist` → `dist`；Dockerfile/README/注释同步。
- 删除临时的 `scripts/copy-dist.mjs`（曾想把 web/dist 复制到根 dist，但本地 git-bash 对 `.mjs` 文件参数有 127 怪癖，且不如单一产物干净）。
- 本地 `npm run build` 验证：仓库根 `dist/index.html` + `dist/assets/*` 正确生成 ✅。

### 经验教训（重要）
- **Cloudflare Pages 控制台「重试部署」只重跑同一条旧 commit**，不包含新修复。必须触发基于最新 commit 的新部署（Deployments 列表应出现新 commit，或点 Create new deployment 选 main）。
- **不要点旧部署详情页的 Retry**；要看最新 commit 是否进了部署列表。
- 沙箱 Bash 里 `node` 不在 PATH，直接 `node scripts/x.mjs` 会 127；但 `npm run build` 内部 npm 自带 node 可正常执行。验证用 `npm run build` 整条跑 + `ls dist`，而非单独调 node 文件。

### 无状态架构：回合快照 + 决策日志重放
- 引擎是长驻异步状态机，但 Workers 无常驻内存。解法：每个 2s 前端轮询调 `stepGame()`：①读回合起点快照 + `restore()` 引擎；②重放本回合已落库决策日志（纯 CPU）；③最多推进 `budget` 个真实 LLM 决策后让出；④写新事件+日志到 D1；回合完成则写前进后的快照。重放只回溯到回合起点 → CPU ∝ 单回合决策数(~20–30)，与整局长度无关。
- **不变式（真校验）**：所有引擎 `emit` 每次重放必须无条件执行，只有「journal 消费」可分支，否则 `seq` 错位。校验用「快照前缀一致性」：前一快照完整事件列表必须是后一快照（按 `seq|type|payload` digest）的前缀。单快照 seq 检查抓不到「重放改写已提交事件」。
- budget 映射 `fast→4 / normal→2 / slow→1`；`AWW_STEP_BUDGET` 可覆盖（clamp 12）。
- 真人：新增 `humanDecide` hook，发 `human_turn`（总是）→ 查 journal → `human_inbox` → deadline 超时 `autoDecisionFor` → 否则抛 `PendingHumanSignal`；提交动作存 `human_inbox(game_id,round,idx,seat,payload)` 按 (round,idx) 消费，天然幂等。超时 fast45/normal90/slow120s。
- 乐观并发 `game_runtime.lock_until`(30s)；Web Crypto AES-256-GCM（`worker/webcrypto.ts`）与 `server/src/crypto.ts` 字节兼容；master key 取 `AWW_MASTER_KEY` 或 D1 `app_meta` 自生成。
